# 单词拼读王：把宠物陪伴接回单词学习

## 产品问题与职责

单词拼读王与悦读小达人是两款独立产品。本案例围绕单词学习体验、宠物互动与品种扩展展开；本人负责问题定义、需求取舍、PRD 与原型迭代，Agent 辅助资料整理、代码和视觉探索。产品品牌与既有插画不全部归于本人独立创作。

产品已有主 IP 梨宝与十二种宠物，学习达到标准后可手动领取经验或食物、喂食并提升宠物等级。此次问题不是从零设计喂食，而是如何增强宠物与学习过程的联动，同时控制素材生产和弱网加载成本。

## 关键取舍

1. **学习主线优先。** 将普通步骤的轻反馈、一个单词第六步后的完整庆祝和首次带宠物入场分开。庆祝需要与真实完成相连，避免每次操作都重复打断。
2. **四级门槛来自产能约束。** 用户明确指出四级宠物伴学是当前素材产能限制下的选择，不将其包装成已由数据证明的最佳门槛。先验证一个角色和复用编排，再讨论十二种宠物扩展。
3. **测试位置不是最终布局。** 步骤条上的梨宝曾用于原型测试，用户随后明确不是正式稿件。伴学方案按整个学习容器的安全区域讨论，避开题目、选项、输入框与键盘；最终位置仍需原型评审。
4. **技术分期。** 现有 JSON 是携带图片的逐帧动画，不能因扩展名是 Lottie 就当作可编辑矢量。新品种方案沿用现有序列帧技术，保留分层源文件和动作映射，为后续矢量或骨骼实现留出验证空间。
5. **控制扩展面。** 猫咪上新同步梳理成长等级、待机/喂食/点击互动、音效、配饰适配与埋点。用户随后要求升级演出供所有宠物复用，日常一种交互方式对应一种动作；不能用旧的随机点击原型替代猫咪新方案。动作数量、收费及配饰分期以评审结果为准，不把早期建议当成已上线配置。

## 已有产物

- 六步学习原型：学、读、选、拆、拼、写，以及计划页与学习页切换、切词、作答、录音回放、默写输入和反馈状态。存在可运行的本机 HTML/JS 产物；示例词库和学习进度不是线上用户数据。
- 宠物动作与音效原型：探索点击互动、连续点击反馈、喂食和奖励；已有可离线分享的 HTML 产物。这是原型验证，不等于正式 APP 已按同样规则上线。
- 宠物伴学 PRD：记录四级门槛、首次入场、每词完成庆祝、素材复用和状态边界。部分本地早稿仍保留旧的步骤条位置，案例以用户后续纠正为准。
- 猫咪上新 PRD 与风格探索：用户反馈已进行问卷并有猫咪需求，但目前未核验问卷样本、选项占比或正式统计。公开风格图为 Agent 辅助探索，不称最终定稿或用户调研结果图。

网站两张学习图于 2026-10-21 从现存本机原型重新渲染；猫咪图复用现存 PRD 风格探索素材。三者均不是线上客户端截图。

## 困难与处理

| 困难 | 处理方式 | 当前边界 |
| --- | --- | --- |
| 宠物、等级和动作的组合放大资源成本 | 区分位图逐帧与矢量实现，先验证单角色，复用位移、入场和庆祝编排 | 未取得跨角色资源体积或弱网性能收益实测 |
| 早期测试稿被误当最终方案 | 回查用户原话，保留纠正与版本边界，按安全区域重新讨论 | 现有截图用于说明原型，不代表最终伴学布局 |
| 正反馈变成学习打断 | 区分普通反馈与每词完成庆祝，明确首次/重复进入及关闭状态 | 仍需验证继续学习、关闭率和干扰程度 |
| 新品种同时带来成长、动作与配饰适配 | 将素材量、动作语义、音效优先级与分期一起评审 | 不承诺全部等级或配饰已制作完成 |

## 实验与数据边界

本人在历史对话中确认：单词拼读王做过 A/B 测试；悦读小达人当时没有。当前资料尚不足以核验实验对象、版本、随机分流、样本量、周期、指标、显著性或结果，因此本案例不填写实验提升数字，也不把该历史实验自动归为这次宠物伴学或猫咪上新的验证。

悦读小达人的双端活跃、启动和留存数据属于另一产品，不作为单词拼读王的效果证明。后续应单独取得实验方案、分组报表、曝光口径、主指标与护栏指标，核验后再形成实验复盘。

## 可展示的能力

把学习体验、情绪反馈与生产约束放到同一需求中取舍；通过可操作原型核对状态；区分正式产品事实、用户提出的方向、Agent 建议和待验证结果。当前成果是需求与原型证据，不以未核验的上线收益包装成效。
