# 悦读小达人：让学习行为形成奖励闭环

## 产品问题与职责
学习任务完成后，奖励需要足够具体、可理解、可消费，同时避免装扮玩法挤占学习主线。本案例展示需求拆解、星币规则、入口与状态设计、原型验收及上线后的数据观察。需求取舍由本人主导；代码与部分素材使用 Agent 辅助；品牌插画与既有产品视觉不全部归于本人独立创作。

## 关键决策
- 从绘本单点扩展到全学习链路，奖励以有效学习完成为依据。
- 关注多孩资产隔离，奖励与事件关联 child_id / profile_id。
- 小屋、背包、图鉴形成兑换与放置闭环；同时覆盖星币充足、不足、取消和返回学习。
- 将需求、状态、埋点目的与验收路径关联，避免仅交付成功态页面。

## 数据观察
Android + iOS 全 APP：上线前 2026-07-07—08-03 与上线后 2026-08-04—08-31，各 28 个自然日。正式上线日 08.04 已由本人确认。2026-10-19 通过已登录的友盟 U-App 页面分别选择双端导出，再从报表中心下载 22 张 CSV，共 7,519 行；不是 SQL 查询或逐条用户行为日志。趋势每端覆盖 104 天，事件按日/事件/版本汇总，留存每端覆盖 103 个日批次。2026-10-20 将四张合并表与原始表逐字段对账后重算。

| 指标 | 上线前 | 上线后 | 相对变化 |
| --- | ---: | ---: | ---: |
| 日均活跃用户 | 13,079.29 | 16,134.64 | +23.36% |

日均活跃 = 双端每日 DAU 求和 / 28；日均启动 = 双端启动总次数 / 28；每活跃用户日启动 = 启动总次数 / 活跃用户日。前后活跃用户日分别为 366,220 与 451,770，启动总次数分别为 1,075,725 与 1,356,472。双端未跨端去重，累计用户日不是期间去重用户。

新用户留存按成熟且非空的同批次基数加权，前后每端均有 28 个完整批次。D7 为 9,745/47,075 → 9,005/39,690，即 20.70% → 22.69%（+1.99 个百分点）；D30 为 11.34% → 12.33%（+0.99 个百分点）。留存率上升时，留存人数实际下降，不能写成回访人数增加。

## 业务解读与下一步
启动增长以活跃规模扩大为主，人均频次变化较小；新增用户同期下降，需要进一步核对存量回访、获客与用户结构。Android 人均频次 +0.88%，iOS +5.56%，两端存在差异。悦读当时没有 A/B 测试，可能受版本、投放、假期与开学季影响，不能宣称游戏化单独带来 23.36% 增长。下一步应核对 iOS 埋点覆盖，按渠道、版本、新老用户分层，并关联学习完成、奖励领取与后续回访。单词拼读王的 A/B 测试属于另一独立案例。
