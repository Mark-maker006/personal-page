# 悦读小达人：让学习行为形成奖励闭环

## 产品问题与职责
学习任务完成后，奖励需要足够具体、可理解、可消费，同时避免装扮玩法挤占学习主线。本案例展示需求拆解、星币规则、入口与状态设计、原型验收及上线后的数据观察。需求取舍由本人主导；代码与部分素材使用 Agent 辅助；品牌插画与既有产品视觉不全部归于本人独立创作。

## 关键决策
- 从绘本单点扩展到全学习链路，奖励以有效学习完成为依据。
- 关注多孩资产隔离，奖励与事件关联 child_id / profile_id。
- 小屋、背包、图鉴形成兑换与放置闭环；同时覆盖星币充足、不足、取消和返回学习。
- 将需求、状态、埋点目的与验收路径关联，避免仅交付成功态页面。

## 真实产物
网站图片来自既有本地 HTML Demo，本轮于 2026-10-19 重新渲染；它们展示交互原型，不是线上客户端截图。导航对比图来自历史评审产物，代表方案对比。

## 数据观察
Android + iOS 全 APP：上线前 2026-07-07—08-03 与上线后 2026-08-04—08-31，各 28 个自然日。正式上线日 08.04 已由本人确认。2026-10-19 通过已登录的友盟 U-App 页面分别选择双端导出，再从报表中心下载 22 张 CSV，共 7,519 行；不是 SQL 查询或逐条用户行为日志。趋势每端覆盖 104 天，事件按日/事件/版本汇总，留存每端覆盖 103 个日批次。2026-10-20 将四张合并表与原始表逐字段对账后重算。

| 指标 | 上线前 | 上线后 | 相对变化 |
| --- | ---: | ---: | ---: |
| 日均活跃用户 | 13,079.29 | 16,134.64 | +23.36% |
| 日均启动次数 | 38,418.75 | 48,445.43 | +26.10% |

日均活跃 = 双端每日 DAU 求和 / 28；日均启动 = 双端启动总次数 / 28；每活跃用户日启动 = 启动总次数 / 活跃用户日。前后活跃用户日分别为 366,220 与 451,770，启动总次数分别为 1,075,725 与 1,356,472。双端未跨端去重，累计用户日不是期间去重用户。

新用户留存按成熟且非空的同批次基数加权，前后每端均有 28 个完整批次。D7 为 9,745/47,075 → 9,005/39,690，即 20.70% → 22.69%（+1.99 个百分点）；D30 为 11.34% → 12.33%（+0.99 个百分点）。留存率上升时，留存人数实际下降，不能写成回访人数增加。

## 业务解读与下一步
启动增长以活跃规模扩大为主，人均频次变化较小；新增用户同期下降，需要进一步核对存量回访、获客与用户结构。Android 人均频次 +0.88%，iOS +5.56%，两端存在差异。悦读当时没有 A/B 测试，可能受版本、投放、假期与开学季影响，不能宣称游戏化单独带来 23.36% 增长。下一步应核对 iOS 埋点覆盖，按渠道、版本、新老用户分层，并关联学习完成、奖励领取与后续回访。单词拼读王的 A/B 测试属于另一独立案例。

## 边界
事件表没有用户标识或发生顺序，不能计算用户级漏斗。首个 28 天，Android 小屋主事件有 28 天记录；iOS 小屋访问只有 26 天、去阅读点击 16 天、绘本完成 22 天。缺失可能是无触发、未上报或版本差异，不能自动补零或当作功能流失。7月7日至12日没有事件源记录；上线前阅读事件较少且出现测试事件，不能声称阅读完成率提升。事件版本含 null，尚未完成版本控制。原始表只保存在本机；公开聚合结果、公式和分子分母见 [yuedu-metrics.json](yuedu-metrics.json)。

# 竞品研究：把观察转成我方产品决策

## 研究问题与职责
研究儿童阅读产品的内容组织、学习路径、受限状态与回访体验。本人负责研究问题、证据组织与我方策略取舍；Agent 辅助检索、ADB 操作、资料整理和图文排版。

## 方法
1. 公开资料建立产品形态与商业模式地图。
2. 使用实际路径走查，区分游客、登录非会员、会员及权限限制。
3. 把截图放在对应论点旁，标记观察、推断、建议与待验证。
4. 以“操作—预期—实际—结论”复核关键交互。
5. 将竞品机制转为我方可借鉴内容、边界、优先级与验证指标。

## 真实发现
叫叫 App 历史走查中，主视觉入口一次点击可进入播放；快捷入口需要两次点击；最近浏览仅记录到系列层级；一次断点续播测试从《足球！不止冠军》00:47 返回后，打开了《阿特拉斯雄狮-摩洛哥》且从 00:00 开始。此为当次环境的路径观察，不能外推所有版本均如此。

## 产物说明
市场地图图片来自既有交互汇报原型，本轮重新渲染；会员受限内容流程图来自真实评审产物；播放结果图来自历史 ADB 走查证据。竞品 UI 与品牌归原权利人，展示仅为研究论据，不属于本人设计作品。

## 困难与解决
初稿曾偏向“替竞品提建议”，经评审将行动主体统一为我方。单独列出截图无法支撑判断，因此改为证据就近组织；无法取得的会员状态明确列作缺口。旧版资料不能当成新版事实，悦读小达人、叫叫 App、叫叫绘本按产品身份分别取证。

## 边界
本案例不声称完整覆盖全部竞品、已验证市场规模或实现业务增量。公开页面仅摘录不含账号与个人信息的截图及方法说明。

# Agent 动画工具箱：把重复失败变成可恢复流程

## 产品问题与职责
视频参考、SVG 部件、Lottie 工程及播放器之间有多处失真风险：参考未传入、位图替代矢量、局部动作缺失、连续帧跳变、长任务中断。本人定义需求、验收与交付边界，Agent 辅助实现插件和实际试作。

## 工作流
素材准备 → 动作参考 → 部件映射 → Creator 制作 → 机械结构、连续运动和参考视觉三类验收 → 用户确认 → 正式交付。任务规格与阶段证据留存在本地状态中，恢复时读取已有任务而非重建。

## 真实产物
- Creator 工程截图：历史真实编辑器截图，显示部件与时间轴。
- 逐帧联系表：历史实际播放器渲染的两秒预览。
- MP4 与 Lottie JSON：同一两秒工作预览，用于展示和评审。

该版本为 512×512、30 fps、2 秒，JSON 有 26 个 shape 图层，无外部图像资产。公开文件仅含动画图层，不包含任务配置、Creator 身份、接口凭据和原始日志。

## 困难与解决
不把“RGBA”“机械检查通过”当成视觉通过；逐帧看眉眼、嘴型与连续动作。参考、部件、工程身份不一致时停止写入。将视频生成任务 ID 与阶段产物保存，便于超时后继续检查。

## 成果边界
插件已有版本与隔离安装验证，当前两秒动画仍是待人工确认的工作预览。基线实验未重现关键错误，不能声称工具让成功率提高多少；多模型、多播放器、多素材回归仍不足。未验证节省工时和商业收益，因此不写虚构效率百分比。
